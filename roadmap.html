Vision Node: low-cost mapping and GNSS-denied navigation

A concept add-on module: one downward-facing camera node doing both jobs — navigation aid and mission-planning map — instead of separate sensors for each. It's designed to offset the optical flow sensor already in the navigation BOM, not add to it.

Function Output
Visual odometry Ground velocity and drift correction for the flight controller's state estimator, in real time.
Map-relative fix Absolute position without GNSS, roughly once per second.
Rough map Orthomosaic and elevation preview on board; full-resolution product processed on the ground.
Points of interest Bridges, roads, blocked access, damaged buildings — flagged on the ground today, on board in a later iteration.

A layered approach to navigating without GNSS

Layer Method
Relative Visual odometry fused with baro and IMU — drifts slowly instead of the fast drift of inertial sensing alone.
Self-built map Map the ingress path while GNSS is still available, then relocalise against it once jammed ("teach and repeat").
Reference map Match live frames against a preloaded orthophoto, using roads and rivers as persistent features.
Spoof check Compare the vision-based position against GNSS; a mismatch flags possible spoofing.

Development roadmap

1

Ground Mapping

Geotagged capture, processed on the ground. Validates image quality and the map product.

2

Onboard Odometry

Visual odometry feeding the state estimator, tested first in simulation and replayed flight logs.

3

Relocalisation

Teach-and-repeat, then reference-map matching against a preloaded orthophoto.

4

POI Detection

Ground-side ML moving on board over time, exported to C2 for situational awareness.
